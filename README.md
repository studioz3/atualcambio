# Atual Digital Gateway

Vamos criar o novo site da atual cambio (atualcambio.com.br)

Design System v1 — Atual Câmbio

1. Princípio da experiência

O novo ambiente digital da Atual deve transmitir:

Autonomia + orientação + segurança + agilidade.

Proposta de valor:

Plataforma digital quando você quer autonomia. Especialista quando você precisa de orientação.

Explicação:

Atendimento consultivo com tecnologia para simplificar e agilizar as operações, sempre com segurança.

Posicionamento institucional:

Se você pensa global, você é Atual.

2. Personalidade visual

O site deve parecer:

sofisticado sem ostentação;

contemporâneo;

financeiro sem parecer bancário;

tecnológico sem parecer uma fintech genérica;

humano sem parecer informal demais;

global;

seguro;

preciso;

simples de usar.

Evitar

excesso de dourado;

gradientes chamativos;

neon;

efeitos “cripto”;

excesso de glassmorphism;

sombras pesadas;

cards em excesso;

ícones genéricos dominando a interface;

imagens clichê de notas e moedas;

aparência de exchange especulativa;

aparência de banco tradicional.

Prioridades mobile:

WhatsApp;

app;

43. Acessibilidade

Obrigatório:

contraste AA;

navegação por teclado;

focus visível;

textos alternativos;

labels;

tamanho legível;

mensagens de erro compreensíveis;

não depender apenas de cor;

respeitar prefers-reduced-motion.

44. Performance

Prioridade alta.

Usar:

WebP/AVIF;

lazy loading;

responsive images;

fontes otimizadas;

scripts controlados;

evitar vídeos pesados no hero;

carregamento assíncrono quando possível.

45. Analytics

Exemplos:

data-event="open_account"

data-event="whatsapp"

data-event="stablecoin_buy"

data-event="pj_lead"

data-event="remittance_start"

A implementação será conectada ao GTM/GA4.

49. Regras para o Lovable

Ao construir qualquer página:

usar este Design System;

manter a Home criada anteriormente apenas como referência visual;

não copiar literalmente sua arquitetura antiga;

priorizar mobile;

usar componentes reutilizáveis;

evitar hardcode desnecessário;

separar conteúdo de componente;

preparar campos para analytics;

preparar integrações por API;

preservar acessibilidade;

otimizar performance;

nunca inventar cotação;

nunca inventar prazo;

nunca inventar dados institucionais;

marcar dependências ainda não validadas.

50. Dependências da ONZ

Marcar no desenvolvimento:

[AGUARDANDO API ONZ]

para:

cotação de moedas;

cotação USDT;

cotação USDC;

deeplinks;

atribuição de app;

onboarding;

identificação de cliente;

outras funções transacionais.

A ausência dessas integrações não deve impedir a construção do front-end.

51. Arquivos de marca

Logo, símbolo, selos e demais arquivos oficiais serão adicionados diretamente ao projeto no Lovable.

Nunca recriar o logo por aproximação.

52. Princípio final

Cada decisão de interface deve responder:

Isso ajuda o cliente a entender, confiar ou avançar?

Se não cumprir nenhuma dessas três funções, provavelmente não precisa estar na tela.

O novo site deve ser:

simples para começar, seguro para operar e humano quando o cliente precisar de orientação.
